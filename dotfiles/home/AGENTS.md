# AERISOS system map — persistent agent reference

This is the map of the running system: where data lives and what it means. How the code
is written (shell style, the `bin/` command header, tests, events over polling) is the
contract in `~/aerisos/AGENTS.md`; developer reference pages are in `~/aerisos/docs/`.

Standing knowledge so the agent can answer questions about data seen in the AERIS
dashboard ("when I open AERIS and open code") without re-discovering it each session.
Update this file whenever a data location, threshold or pipeline changes.

## Status board pipeline (what the user sees in the dashboard/TUI)
- Generator: `/home/h/aerisos/status/aeris-status` (Python), run by
  `~/.config/systemd`-side `aeris-status.service` + `.timer`
  (unit files in `/home/h/aerisos/status/aeris-status.service|.timer`).
- Output: `/var/lib/aeris/status.json` (public) and `private.json` (per-source caches:
  `air-cache.json`, `gpsjam-cache.json`, `net-cache.json`, `news-cache.json`,
  `swpc-cache.json`, `tle-cache.json`, `ioda-cache.json`, `lock.tsv`).
- Display: OpenCode plugin `~/.config/opencode/plugins/aeris-board/tui.tsx`
  (reads `s().air.gnss` etc. from the status JSON via Ollama context card).
- Values shown inverted (black on white) when notable; e.g. GNSS jammed, emergency
  squawk, ISS/Tiangong overhead, G1+ storm, internet outage. `STALE` label = failed refresh.

Lock screen (generated by `~/aerisos/lock/make-hyprlock`) and login screen
(`~/aerisos/sddm/aeris/Main.qml`, installed to `/usr/share/sddm/themes/aeris/`) share one
layout, a Swiss grid since 2026-11-13: 12 columns on a 120 step from x=96 in the 1600x900
design space, every baseline on 9 + 18n; decluttered 2026-11-13 (no SYS/00, build label,
status text or hairlines; Nerd Font icons). Feeds in columns 1-9 as two-column tables:
WATCHLIST (8 rows, grouped by topic, the topic on its group's first row, rows shared out
round robin, "+N" for the rest) and WORLD (7 rows, outlet | telegram); telegrams in sentence
case, labels and readouts in capitals; unread telegrams white, read grey. The right column is
one list built by the collector (`side_rows` -> `status.json` `side`, `lock.tsv`
`side.N{h,s,i,v}`): `// CARD` heads, rows of icon (column 10) + value (24 further), quiet
values (GNSS OK, no squawk) left out, a warning glyph on a head whose refresh failed instead of
fetch times. Icons are NotoSansM Nerd Font Mono glyphs (code points in `ICON` in the collector,
`glyph` in `Main.qml`, `GLYPH` in `make-hyprlock`). Login: user/key icons, enter arrow; power
actions as moon/restart/power icons. The grid is documented at the top of `Main.qml` and
`make-hyprlock`. The formatted feed rows are built once in the collector (`watch_feed`,
`telegram_feed`; telegrams cut to `FEED_WIDTH` 90) and published to `status.json`
(`watch.rows`/`more`/`stale`, `world.telegrams`) and, split into cells by
`watch_cells`/`news_cells`, to `lock.tsv` (`watch.N{t,h,hc}`, `news.N{t,h}`), so both screens
show identical lines. Telegram memo entries from the all-caps era are re-asked once. Preview
the login with `sddm-greeter-qt6 --test-mode --theme ~/aerisos/sddm/aeris` (needs
`QML_XHR_ALLOW_FILE_READ=1`).
Watch rows: near-duplicate stories (≥3 shared significant words and ≥60% overlap of the
smaller set, topic name excluded) collapse into the newest; the telegram omits the topic
name since the row already carries it (Ollama prompted with the label, plus a leading-name
strip; memo keys prefixed `@topic|`). The deployed collector is `/usr/local/bin/aeris-status`
(root-owned copy of `~/aerisos/status/aeris-status`; sudo install after editing).

## GNSS alert semantics (air.gnss)
- Metric: among aircraft in the 50 km adsb.fi circle **above 1,000 ft** (surface targets
  excluded — tower beacons and ground vehicles report NACp 0 routinely), count `nac_p < 8`.
  `OK` = fewer than 2, `LOW` = 2 or more, `JAMMED` = 3 or more and >10% share.
- The alert list (`status.json` `alerts`) only fires on the literal string `JAMMED …`
  and emergency squawks etc.; `LOW x/y` is an indicator only — it does not invert the card
  and does not alert. Baseline noise here is the Valencia VFR training fleet (Airpull
  PA-28s, EC-GEG etc.) whose uncertified GPS reads NACp 0 with no interference present.
- To inspect now: `cd /var/lib/aeris && python3 -c "import json; s=json.load(open('status.json'))`
  and read `air-cache.json` / `gpsjam-cache.json`.

## The shell: bar + dock (since 2026-10-24 one Quickshell process)
- `~/.config/quickshell/aeris/shell.qml` (quickshell 0.3.2) hosts the top bar and the bottom
  pill dock. Tree: `Commons/` (`Theme`, `Status`, `Shell` singletons), `Ui/` (`StatusModule`,
  `Glyph`, `Caption`), `Bar/` (one file per widget), `Dock/Dock.qml`. Launched at login from
  `~/.config/hypr/hyprland.lua`; restart: `pkill -f 'qs -p .*quickshell/aeris'` then relaunch
  the same line (or log out/in).
- IPC: `aeris-shell bar toggle|refresh`, `aeris-shell dock reveal|conceal|flip`
  (`aeris-shell -q` quiet). Commands that change bar state push `aeris-shell -q bar refresh`.
- Dock autohide is pointer-driven inside the shell: a 1 px strip on the bottom edge reveals,
  leaving the pill plus a halo hides. The old `dock-autohide` cursor-polling script is gone.
- Quickshell's PATH (inherited from Hyprland) lacks `~/.local/bin`; `Shell.sh()` prepends it
  so click commands can push `aeris-shell -q bar refresh` (without it toggles show stale
  state until the 60 s fallback). Edits to `Commons/` singletons may not hot-reload: restart.
- Theme overrides: `~/.config/aeris/shell.json` (`{"version":1,"colors":{...},"fonts":{...}}`),
  watched live. Status data: `Commons/Status.qml` watches `/var/lib/aeris/status.json`.
- Bar refresh model: StatusModules re-run on IPC refresh, on click, and every 60 s as a
  fallback; drawer modules (bluetooth, power profile, backlight) only while the drawer is open;
  network follows `nmcli monitor` events.
- The Radeon flicker rule for the Studio Display (see "This machine") is unrelated to the shell.

## Other standing infrastructure
- Ask terminal: `aeris-ask-term` (Win+` on the Razer, renamed from aeris-ask 2026-11-13) toggles a Ghostty window (class `aeris.ask`) on
  `special:ask` running an Ollama chat (first installed of qwen3.5:9b, gemma4:e4b, …; override
  `AERIS_ASK_MODEL`). Win+Shift+` sends the primary selection through `$XDG_RUNTIME_DIR/aeris-ask.fifo`.
- Watchlist (news topics, feeds, real-time collection): manage with
  `/home/h/.local/bin/aeris-watch`; findings in `/home/h/.local/share/aeris/watchlist.json`.
  Current items (since 2026-10-21): cfsn-helsing (de-DE), palantir (en+de), anduril (en+de),
  chapsvision (fr+en), helsing (en+de). Since 2026-10-22 the company items (palantir, anduril,
  helsing, chapsvision) watch the plain company names (broadened at the principal's request),
  not just Europe/NATO angles; `cfsn-helsing` stays a focused contract question.
- Watchlist findings history: `ack` moves findings into each item's `archive` (last 500) in
  watchlist.json instead of discarding them; `aeris-watch log [NAME]` prints all of it, and
  every state change rewrites `~/.local/share/aeris/watch.html`, a readable page with per-item
  notes and full article history (unacknowledged marked with a star). Checked hourly
  (aeris-watch.timer).
- Chats/commands: `/watch` (watchlist), `/brief` (situation brief incl. GNSS interference),
  `/inbox` (OpenCode) and `/watch-inbox` (Claude Code): the watchlist as a numbered inbox
  via `~/.local/bin/aeris-inbox`, "open N" for detail, ack per topic.
- Monologue (camera recorder, Win+Shift+7): `~/.local/bin/monologue` wraps `/usr/bin/monologue`
  (holds the webcam at 30 fps via `exposure_dynamic_framerate=0`; on 0.3.x forces libx264 at preset
  veryfast through `~/.local/lib/x264-fast.so`). Built from omarchy-pkgs since upstream dropped its
  PKGBUILD (2026-11-12). Root causes, upstream fixes and the Qt VA-API bug: `~/aerisos/docs/monologue.md`.
- MX Master 3 (Solaar, from tinyraven 2026-11-13): `solaar --window=hide` starts from hyprland.lua;
  `~/.config/solaar/config.yaml` diverts the gesture button (key 195) and the wheel-mode button (196),
  `rules.yaml` maps gestures to `~/.local/bin/mouse-gesture` (tap screenshot area, up launcher, down
  close window, left/right back/forward) and the wheel-mode button to Return (`mouse-gesture enter`; same on tinyraven since 2026-11-13, where Superwhisper, not voxtype, owns the back button). The back button (not diverted, `mouse:275` in hyprland.lua) runs
  `mouse-dictate press|release`: voxtype with auto-submit (Enter); held ≥1 s it stops on release, a
  shorter click keeps recording until the next press. The forward button opens the pet ask.
- Pet ask (from tinyraven, synced 2026-11-13): `aeris-ask` (Super+/ or the mouse forward button)
  opens `ask.qml` under the pet; answers by free OpenRouter models (`OPENROUTER_API_KEY` in
  `~/.env`), commands judged by the Jev model; slash commands (/help /timer /remind /hush /status

  While the pet shows, dunst's `[aeris-pet-notifier]` rules hand notifications to `aeris-pet-notify`

- `open` (folder, file, link or app by name), `aeris-ssh` ("SSH to…" in the launcher: Tailscale

- Swiss grid tiling: `grid` (`grid off`) switches the active workspace to the Lua layout `lua:swiss`

## Razer laptop (hostname rzr since 2026-10-25, was vm)
- Razer Blade 17 (2022, RZ09-0423). SDDM and hyprlock require password + FIDO key
  (`pam_u2f`, mappings in `/etc/u2f_mappings`). The Titan key is U2F-only and shows up as
  `096e:085b` "FS ePass FIDO". The default pam_u2f origin is `pam://<hostname>`, so pin
  `origin=/appid=pam://aeris` in the PAM lines to survive renames.
- GPU: RTX 3070 Ti Laptop (`10de:24e0`, 8 GB, PCI `0000:01:00.0`) + Intel Iris Xe.
  Since 2026-10-29 tensor-core unlock via gpu-unlock (Zagitta, clone `~/src/gpu-unlock`,
  DKMS pkgs `gpu-unlock-dkms/-firmware`): `gpu_unlock.targets=0000:01:00.0` in
  `/etc/kernel/cmdline` (UKI), runtime PM off in `/etc/modprobe.d/nvidia-nopm.conf`.
  Dense matmul before/after unlock: BF16/FP16 34 → 50–54 TFLOPS, TF32 17 → 26 (`~/ml/bench.py`,
  `~/ml/bench-before.txt`, `bench-after.txt`; venv `~/ml`). Verify after boot:
  `journalctl -k -b | grep gpu_unlock` ends in `unlocked`. Toggle with `~/.local/bin/gpu-unlock
  status|on|off|undo` (on/off/undo rebuild the UKI, apply after reboot; `off` lets the GPU sleep
  for battery; `undo` also removes the packages).

## MacBook (since 2026-10-22: hostname AerisT2, was hdls)
- MacBookPro16,1 (Intel T2, Radeon Pro 5300M drives all displays; internal keyboard has
  no Print key or Right Ctrl — dictation is Right Option/Alt, screenshots on SUPER+SHIFT
  letters; see README shortcuts table).
- **Hardware fault**: the Radeon's DP output stage is degraded — at 5K bandwidth it
  produces horizontal-band flicker on every port/display, under macOS too, with no link
  drops and nothing in any log. Diagnosed 2026-10-22 (clocks, heat, link ruled out).
  Workaround: `hyprland.lua` caps the Studio Display at 4K@60, scale 1.25 (3072x1728
  logical; SUPER+SHIFT+plus/minus steps the scale at runtime) via a DMI-keyed rule
  (`MacBookPro16,1`). Do not re-diagnose flicker reports from scratch; if another display
  flickers, cap its mode the same way. True fix would be board-level repair.
- No passwordless sudo: ask the user to run root commands via the `! sudo …` prompt prefix.

## T2 Mac (the other machine, AerisT2 MacBookPro16,1) — boot panic workaround (2026-10-23)
- linux-t2 7.2.x panics at cold boot about every other time ("Fatal exception in interrupt"):
  `t2bce_vhci` (keyboard/trackpad over the T2 bridge) NULL-derefs on the bce_dma IRQ thread
  (t2linux/kernel#37, open, no upstream fix yet). Not Wi-Fi/Bluetooth/amdgpu (all tested).
- Workaround in place: boot entry `arch-t2-vhcilate.conf` ("Arch T2 (vhci late)", default,
  `modprobe.blacklist=t2bce_vhci`) + unit `t2bce-vhci-late.service` loading it 2 s into boot.
  Applied/undone with `~/aerisos/t2/vhci-late.sh` (`| bash -s undo` once upstream fixes it).
- Recovery from the live USB (curl | bash, repo raw URLs): `t2/repair.sh` (reinstall kernel),
  `t2/diag.sh` (journal of failed boots, `DIAG_UPLOAD=1` -> paste.rs), `t2/kernel-downgrade.sh`
  (pin 7.2.8). T2 installer ISO: `T2_FIRMWARE_TAR=~/backups/t2fw/firmware.tar sudo -E iso/build.sh --t2`
  (Apple Wi-Fi firmware backed up in `~/backups/t2fw/`).
